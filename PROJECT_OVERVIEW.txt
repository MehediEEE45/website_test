================================================================================
  WHAT IS THIS PROJECT?
================================================================================

A comprehensive IoT system to monitor a battery's health in real-time using
an ESP32 microcontroller, capturing voltage, current, power, temperature,
state of charge (SoC), and state of health (SoH). The data flows through
MQTT to a Node.js server, gets stored in MongoDB, and is visualized on
a web dashboard.

PURPOSE:
  Monitor a 4200 mAh battery's performance across charging/discharging cycles.
  Track degradation over time (SoH). Detect anomalies. Provide live and
  historical analytics.

USERS:
  - Personal use: Monitor your battery, see charts, get alerts
  - Research: Export data for analysis
  - Maintenance: Check battery health before deployment

================================================================================
  SYSTEM ARCHITECTURE (4 Layers)
================================================================================

  LAYER 1: HARDWARE
  ├─ ESP32-D0WD-V3 (dual-core 240MHz, 512KB RAM, 4MB Flash)
  ├─ INA219 current/voltage sensor (I2C, GPIO4/5)
  ├─ LM35 temperature sensor (GPIO32 analog)
  ├─ OLED display (I2C, GPIO21/22) — shows live status
  └─ 4200 mAh LiPo battery (device being monitored)

  LAYER 2: COMMUNICATION (MQTT)
  ├─ ESP32 publishes to:      battery/data (JSON payload every 5 seconds)
  ├─ ESP32 subscribes to:     battery/recieve (command channel)
  ├─ Server subscribes to:    battery/data + smartpower/+/data + energy/+/+/telemetry
  ├─ Broker: HiveMQ Cloud (wss://0d34f5789e1e4a669367abfe5bd45b15.s1.eu.hivemq.cloud:8884/mqtt)
  └─ Transport: WebSocket + TLS (secure)

  LAYER 3: BACKEND SERVER
  ├─ Express.js app (port 3000)
  ├─ Receives MQTT messages, saves to:
  │  ├─ SQLite (local cache)
  │  └─ MongoDB Atlas (cloud, 30-day TTL, M0 free tier)
  ├─ REST API with 15+ endpoints for stats, trends, export, CRUD, commands
  ├─ WebSocket bridge to forward MQTT to web clients
  └─ NOT DEPLOYED (runs on local Windows PC only) ⚠️

  LAYER 4: WEB DASHBOARD
  ├─ Single Page App: battery-monitor.html (2306 lines, 5 tabs)
  ├─ Hosted on Netlify: https://power-monitor.netlify.app
  ├─ Connects to:
  │  ├─ MQTT (direct WebSocket)
  │  ├─ Backend server (REST API)
  │  └─ MongoDB (read stats, show trends)
  ├─ 5 Tabs:
  │  ├─ Realtime: Live 7 stat cards + 3 charts (V/C, Power, Temp)
  │  ├─ History: Raw data table with configurable time range
  │  ├─ Analytics: 7 summary cards + daily trends + comparison + live recording
  │  ├─ Reports: Battery health report, cycle analysis
  │  └─ Settings: MQTT config, backend URL, commands, data management
  └─ Also available: esp32-battery-view.html (simple 1-page MQTT viewer)

================================================================================
  KEY METRICS & DATA POINTS
================================================================================

  Voltage (V)           : Bus voltage (3.0V - 4.2V for LiPo)
  Current (A)           : Charging positive, discharging negative (-10A to +10A)
  Power (W)             : Calculated as voltage × current
  Temperature (°C)      : LM35 sensor, -20°C to +80°C
  State of Charge (%)   : 0-100%, calculated via Coulomb counting
  State of Health (%)   : Current capacity / rated capacity (19.3% in system)
  Uptime (ms)           : ESP32 uptime since boot

  Collection Interval   : 5 seconds (200 samples/hour)
  Storage Duration      : 30 days (30-day TTL in MongoDB)
  Data Volume @ 30 days : ~518,400 documents (at 5s intervals)

================================================================================
  KNOWN ISSUES & LIMITATIONS
================================================================================

  🔴 CRITICAL
  ├─ Server not deployed (local PC only) — NO 24/7 data collection when PC is off ⚠️
  ├─ Credentials in GitHub (config.h has WiFi/MQTT passwords) — security risk ⚠️
  ├─ No API authentication — anyone with server URL can delete all data ⚠️
  └─ ESH32 command handling minimal — only responds to "TOGGLE", ignores JSON commands

  🟡 HIGH-PRIORITY BUGS
  ├─ SoH is static (19.3%) — never changes during operation (not tracking cycles)
  ├─ SoC drift — Coulomb counting has no voltage-based correction
  ├─ Energy calculation assumes 5s intervals — broken for irregular data
  ├─ No data validation on MQTT messages — any malformed JSON gets stored
  └─ MongoDB fetches ALL documents into RAM — scales poorly with 30+ days of data

  🟠 MEDIUM ISSUES
  ├─ battery-monitor.html is 2300+ lines (monolithic) — hard to maintain
  ├─ No alerts for low voltage/high temperature — silent failures
  ├─ Data limited to 50 live points — only 4 minutes of data on chart
  ├─ SQLite redundant — only MongoDB used, SQLite data never read
  └─ No watchdog timer on ESP32 — can hang indefinitely

  🟡 LOW-PRIORITY
  ├─ No dark/light theme toggle
  ├─ No OTA (Over-The-Air) firmware updates
  ├─ No anomaly detection (sensor glitches stored as-is)
  ├─ No PWA / offline support
  └─ No unit tests or CI/CD pipeline
